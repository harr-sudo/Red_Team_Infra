## Critical (operator-blocking)

### C1. "+ New Deployment" jumps to Configure form, bypassing the family/type wizard step
- **Where:** `webapp/frontend/js/app.js:3346-3402` (`startDraftFlow`)
- **What:** Click "+ New" → operator lands at Configure V2 Identity section with project_name already pre-filled (`c2_adhoc_dev_mozilla_5_0_macintosh_in`). The family selector IS the first thing in Identity, but the auto-named project + the legacy form bleeding through reads like the operator is "already configuring".
- **Repro:** Dashboard → click "+ New Deployment" → expected to see clean "Pick a family" prompt; instead see populated form.
- **Fix scope:** Either (a) drop the project_name auto-prefill until a deployment_type is chosen (read the user-reported "stop auto-generating until type is set"), OR (b) reorder Identity so Family Picker is presented as a distinct landing step before the rest of Identity collapses in.

### C2. Discard draft leaves legacy form rendered alongside V2
- **Where:** `webapp/frontend/js/app.js:13357-13403` (`applyDraftMode`)
- **What:** Operator clicks Discard draft → V2 stays partly visible AND the legacy `.configuration-editor` + `#configure-advanced-details` re-appear. The function's hide-legacy logic only runs in the `isDraft` branch — when state moves to `null` (Discard), the function falls through to the else branch which RE-SHOWS legacy.
- **Repro:** + New Deployment → Discard draft → expected clean state; see double-rendered form.
- **Fix scope:** When transitioning out of draft, also explicitly hide V2's pane AND ALSO sweep legacy back to display: '' only if not in draft. Add a `clearV2State()` call to `discardBtn` click handler. The user actually wants the WHOLE legacy form retired — see M1 below.

### C3. AWS & SSH Prereqs overlay has no visible initial loading state
- **Where:** `webapp/frontend/js/app.js:33241-33305` (`renderOverlay_Prereqs`) + `:33427-33436` (`openPrereqs`)
- **What:** Operator opens the prereqs widget. Async fetches to `/api/aws/credentials`, `/ssh-key`, `/permissions`. Before they resolve, overlay should show "Running prerequisite checks…". The `_loadingHost` IS passed as initial content but it's plain text with no spinner — doesn't visually communicate "loading", just looks like idle copy.
- **Repro:** Throttle network → click prereqs widget → first ~500ms shows static "Running prereqs…" text → suddenly flips to OK/OK/OK. No loading animation.
- **Fix scope:** Add a CSS spinner to `.app-overlay__loading` (animated dots or a SVG spinner). Apply across the 6 overlays that share this pattern.

### C4. `__draft__` sentinel leaks into Manage fleet table
- **Where:** `webapp/frontend/js/app.js:30474-30565` (Manage fleet renderer)
- **What:** When operator has a draft in flight AND switches to "All deployments", the fleet table loop iterates over the deployments list but doesn't filter the draft sentinel — renders a row with empty type / empty cost.
- **Repro:** + New Deployment (don't save) → switch dropdown to "All deployments" → Manage → see empty row.
- **Fix scope:** Add a `if (name === DRAFT_SENTINEL || name === ALL_SENTINEL) continue;` at the top of the fleet row loop. Same pattern likely needed in any other places that iterate the deployment list (the Operations aggregate views were already fixed).

### C5. Configure sections don't reset when operator switches family
- **Where:** `webapp/frontend/js/app.js:12785-12795` (`renderSectionSummary`)
- **What:** Operator picks family C2 → Identity confirmed → moves to Network → switches family to GOAD → expected: V2 resets to empty skeleton with new family-appropriate sections. Actually: Identity stays confirmed, Network is gone, the visible TOC rail is stale.
- **Repro:** + New Deployment → pick c2-adhoc → confirm Identity → flip to GOAD-only family → see inconsistent state.
- **Fix scope:** On family change, call `fullReset()` (which already exists at line 12688) or a narrower `resetDownstreamSections()` that clears confirmed state for all sections except Identity and re-runs `applyTypeAwareVisibility()`.

### C6. Test Lab toggle missing from Combined family + cost doesn't recalculate
- **Where:** `webapp/frontend/js/app.js:12211-12220` (Test Lab section visibility) + `:12825` (`updateTestLabVisibility`)
- **What:** The Test Lab section only renders when `family === 'c2'`. Combined deployments (which also have a C2 component) can't add the test lab. AND when the toggle flips on, `renderCost()` isn't called, so the cost line doesn't update.
- **Fix scope:** Extend visibility condition to `family === 'c2' || family === 'combined'`. Call `renderCost()` after the toggle handler. Both ~5 lines.

## High (clearly broken but workaround-able)

### H1. Discard draft banner visible even when no draft exists
- **Where:** `webapp/frontend/js/app.js:3388-3400`, `webapp/frontend/index.html:620-625`
- **What:** The `#configure-discard-draft` banner has `hidden` by default but is never re-hidden when draft state ends. After Discard, the banner ("Composing a new deployment") stays visible.
- **Fix scope:** Subscribe to `draftProject` / `isDraft()` changes and toggle the banner's `hidden` attribute reactively.

### H2. Bolt-ons sub-pill visible for c2-* without test lab
- **Where:** `webapp/frontend/js/app.js:2132-2147` (`computeVisibleSubPills`)
- **What:** The gate is `isC2only && hasTestLab()`. But `hasTestLab()` reads from `APP.activeDeployment.enable_test_lab` which is populated by `_setActiveDeploymentType`. That helper only sets `deployment_type`; the new `enable_test_lab` field isn't always populated on first dropdown change.
- **Repro:** Pick an existing c2-only deployment that DOESN'T have test_lab → Bolt-ons sub-pill appears briefly then disappears (or stays).
- **Fix scope:** Verify `_setActiveDeploymentType` writes BOTH `deployment_type` AND `enable_test_lab` from the cached deployment record. Make sure the cache from `/api/deploy/active` includes `enable_test_lab` per project.

### H3. V2 Save button can be double-clicked → duplicate POST
- **Where:** `webapp/frontend/js/app.js:13347` (`saveBtn` handler)
- **What:** No disable-during-submission on the Save button.
- **Fix scope:** Disable button until response arrives. ~3 lines.

### H4. Configure context banner doesn't refresh after Discard
- **Where:** `webapp/frontend/js/app.js:2439-2451` (`_refreshConfigureContextBanner`)
- **What:** Banner shows "Editing <project>" but doesn't update when activeDeployment.set(null) fires from Discard.
- **Fix scope:** Verify subscriber fires on `set(null)`. Add `_refreshConfigureContextBanner()` call to the discard handler explicitly.

### H5. Pattern — 6 overlays use `_loadingHost` but only 1 is timeout-protected
- **Where:** `webapp/frontend/js/app.js:32843` (Beacons), `:32957` (Activity), `:33044` (Deployment), `:33107` (Cost), `:33184` (Failed), `:33241` (Prereqs)
- **What:** If any promise stalls or errors silently, the overlay shows the loading state forever. No timeout, no error state, no retry.
- **Fix scope:** Add a `_safeAsyncOverlay(promise, host, { timeoutMs: 8000, onError })` wrapper. Apply across all 6.

## Pattern-level recommendations

### P1. Unified loading-state component
Build `APP.overlay._withAsyncBody(host, promise, { timeoutMs, onError })` that:
- Mounts a spinner-animated loading state immediately
- Awaits the promise
- Swaps in content on resolve
- Swaps in an error card with retry on reject or timeout

Apply across all 6 overlays. Eliminates C3 + H5 + L1 in one pass.

### P2. Sentinel filter helper
A single `APP.activeDeployment.isUserVisibleProject(name)` that returns false for the 2 sentinels and empty/null. Apply at every renderer that iterates the deployment list (fleet table, top-bar dropdown, audit log, presence service).

### P3. Reactive UI shells
Banners that depend on activeDeployment state (`#configure-discard-draft`, configure context banner, V2 hero pill, top-bar trigger label) should all wire to the SAME subscriber that ensures every reactive surface is in sync. Today each is wired individually and one or more get missed on certain transitions (Discard being the prime offender).

### P4. Phase out the legacy form
The legacy `.configuration-editor` + `#configure-advanced-details` is the source of multiple bleed-through bugs. Once the Manage edit drawer is decoupled from the legacy field IDs, delete the whole block. Today it's just dead weight that occasionally surfaces wrong.
