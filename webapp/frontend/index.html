📋 Domain Setup Checklist
  • Register domain with a registrar (Namecheap, GoDaddy, etc.)
  • Use an aged domain (6+ months) for better reputation
  • Get domain categorized as "Business/Technology" in web filters
  • After deployment, copy AWS name servers from output
  • Update your registrar's DNS settings with AWS name servers
  • Wait for DNS propagation (check with dig or nslookup)

ℹ️ How Let's Encrypt Works

  1. Initial Boot: Redirector starts with a temporary self-signed certificate
  2. DNS Check: Every 5 minutes, checks if DNS resolves to the redirector
  3. Auto-Request: Once DNS is ready, automatically requests Let's Encrypt certificate
  4. Auto-Renewal: Certificates auto-renew before expiry (90-day validity)

🎭 Malleable C2 Profile (Advanced)

The redirector uses nginx to route C2 traffic. URIs must match your Cobalt Strike Malleable C2 profile.

Select a profile that matches your Malleable C2 configuration

🔴 Critical OPSEC Note

You MUST customize the redirector nginx configuration to match your actual Malleable C2 profile URIs. The default configuration includes example patterns that may not match your profile.

📖 How to Customize Redirector URIs

After deployment, SSH into the redirector and edit:

sudo nano /etc/nginx/sites-available/c2-redirector

Update the location blocks to match your Malleable profile's:

  • http-get { uri } - GET request URIs
  • http-post { uri } - POST request URIs
  • http-stager { uri } - Stager URIs

Then reload nginx: sudo systemctl reload nginx

Only applies to Purple Team (redundancy mode). Adhoc always deploys 1, Full Red Team always deploys 3 (one per phase).
Applies to Adhoc and Purple Team. Full Red Team uses per-phase instance types (default: t3.medium).

✅ Deployment Successful - Next Steps

1. Update DNS (Required)

Copy the AWS name servers from the Terraform output and update your domain registrar. DNS propagation takes 15 minutes to 48 hours.

2. Wait for SSL Certificate (Automatic)

Once DNS propagates, the redirector automatically requests a Let's Encrypt certificate. Check status by SSH'ing into the redirector:

ssh -i ~/.ssh/your-key.pem ubuntu@REDIRECTOR_IP cat /opt/ssl-status.json
3. Customize Redirector URIs (Critical for OPSEC)

SSH into your redirector and edit the Nginx config to match your Malleable C2 profile URIs:

sudo nano /etc/nginx/sites-enabled/default sudo nginx -t && sudo systemctl reload nginx
4. Configure Cobalt Strike

Connect to your C2 team server and configure your Malleable C2 profile to use your domain. Set the host header to match your configured subdomain.

5. Test Connectivity

Test that your domain resolves correctly: curl -k https://api.yourdomain.com/health

💡 Tip: Go to the Deployment Manager page for connection details, IPs, and SSL status.

⚡ Lifecycle Management

💡 How Stop/Start Works: Only EC2 instances can be stopped and started. Other resources (VPCs, NAT Gateways, Elastic IPs, S3) remain active and may still incur charges. To fully stop all billing, use Destroy Infrastructure instead.

⏸️ Stop EC2 Instances

Pause compute without deleting. All EC2 instances (C2 servers, jumpbox, Windows VMs) will be stopped. Data and configuration preserved.

✅ Stops: EC2 compute charges (~60-80% savings)
⚠️ Still billed: EBS storage (~$0.10/GB), NAT Gateway (~$32/mo), idle Elastic IPs (~$3.60/mo each)
💾 Preserved: All data, IPs, security groups, VPC

▶️ Start EC2 Instances

Resume stopped instances. Bring your EC2 instances back online. All configurations and data preserved from when you stopped.

🔄 Restores: All EC2 instances to running state
⏱️ Time: ~2-5 minutes to fully boot
📝 Note: Public IPs preserved (Elastic IPs assigned)
